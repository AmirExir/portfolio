# Portfolio Reviewer

## Use this skill when

Use this skill for repository audits, README improvements, project selection, code-quality review, architecture documentation, demo preparation, recruiter-facing messaging, or portfolio restructuring.

## Review priorities

1. Clear problem and user
2. Demonstrated engineering impact
3. Working and reproducible code
4. Credible metrics and validation
5. Strong documentation
6. Professional repository structure
7. Easy demonstration
8. Honest limitations

## Required workflow

1. Inventory projects and identify duplicates or abandoned work.
2. Select flagship projects aligned with the target role.
3. Review README, setup, architecture, tests, and deployment.
4. Verify that claims match the implemented code.
5. Identify the highest-impact improvements.
6. Separate recruiter-facing presentation from deep technical documentation.
7. Produce a prioritized remediation plan.

## Recommended flagship categories

- Grid Automation: PSS/E and transmission-study automation
- Grid Intelligence: forecasting, faults, optimization, GNNs, or RL
- Grid Knowledge: ERCOT regulatory RAG and evidence systems

## README standard

Each flagship README should include:

- one-sentence value proposition
- problem and engineering context
- architecture diagram
- key features
- installation
- quick start
- example inputs and outputs
- validation and metrics
- screenshots or demo
- limitations
- roadmap

## Claim rules

Avoid unsupported phrases such as:

- production-ready
- enterprise-grade
- autonomous engineer
- zero hallucinations
- guaranteed reliability

Replace them with verifiable evidence.

## Review output

Classify findings as:

- Critical
- High impact
- Medium impact
- Optional polish

For each finding, include the problem, why it matters, and the exact recommended change.

## Completion format

Report:

- Portfolio positioning
- Strongest projects
- Credibility gaps
- Repository issues
- Prioritized next actions
